# Services: Companion Containers — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `services:` field to tpd profiles that declares companion containers (daemons) which start before the main container and stop after it, exposing sockets the main container mounts.

**Architecture:** A `Service` is a mini-profile (image/packages/caches/command/exposes) merged through the extends chain like any other map field. The `Service` struct includes all profile fields (even rejected ones like `network`/`ports`/`devices`) so YAML captures them and validation can reject them. At launch, `LaunchWithWriter` calls `StartServices` (acquires per-service lockfiles in **sorted** order, finds-or-starts each service, returns socket bindings + a release func). Then `CreateContainer` creates the main container (still under the lock, so the `tpd.uses-service` label is visible to a concurrent stop step). Then `release()` drops the locks. Then `RunContainer` starts+waits. A `defer`'d `StopServices` is registered **before** `StartServices` so it runs on every exit path.

**Tech Stack:** Go 1.25, cobra CLI, docker/docker client library, gopkg.in/yaml.v3, github.com/distribution/reference. CGO off. Tests via `go test ./...`. Lint via `go vet ./...`.

## Global Constraints

- Go 1.25, CGO disabled in releases.
- `go test ./...` and `go vet ./...` must pass after every task.
- No comments unless the code doesn't make something apparent (AGENTS.md rule).
- Conventional commit format (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`).
- Profile names match `profileNameRe`: `^[a-zA-Z0-9][a-zA-Z0-9._-]*$`.
- Services are allowed in both profiles and fragments.
- The `Runtime` interface grows from 2 to 5 methods (`Prepare`, `CreateContainer`, `RunContainer`, `StartServices`, `StopServices`); `FakeRuntime`, `runtime_test.go`, `docker_test.go`, and all callers must be updated in the same task as the interface change.
- `StartServices(ctx, spec Spec, w ProgressWriter, pull bool)` takes a `ProgressWriter` (for image pull progress) and a `pull bool` (forwarded from `--pull`), matching `Prepare`'s signature. `StopServices(ctx, spec Spec)` takes neither.
- The `Service` struct includes **all** profile fields (including rejected ones: `Version`, `ExtendsList`, `Network`, `TTY`, `Resources`, `Tools`, `Dbus`, `Ports`, `Devices`, nested `Services`) so YAML captures them and validation can reject non-zero values. Without the fields on the struct, yaml.v3 silently drops them.
- The definition hash is computed in `ResolveProfile` (merge.go) over the **unresolved** `profile.Service` (before `ResolveTildes`), stored on a `Hash string` field on `Service`, and carried to `ServiceSpec.Hash` by `buildSpec`. The hash includes `Caches` and `Labels` (changing caches changes runtime behavior).
- The lockfile (`~/.local/share/tpd/svc-<name>.lock`) is held from the start/reuse decision through the main container's `ContainerCreate`. `StartServices` returns a `release func()`; `launch.go` calls it after `CreateContainer` returns, before `RunContainer`. Locks are acquired in **sorted service-name order** to prevent deadlock across concurrent launches sharing multiple services.
- `Run` is split into `CreateContainer` (create + write files) and `RunContainer` (attach + start + pump + wait). **All existing `Run` behavior must be preserved verbatim** — especially the Ctrl+Z/SIGTSTP suspend goroutine and the 0x1A byte interception in the stdin pump. The `defer ContainerRemove` lives in `RunContainer` (it covers the whole attach/start/wait lifecycle). `CreateContainer` removes the container **explicitly on its own error path only** (e.g. `writeContainerFiles` failure) — it does NOT defer-remove, because `RunContainer` must run after `CreateContainer` returns successfully. Existing callers of `Run` are updated to `CreateContainer` + `RunContainer`.
- Service container names use `Spec.Workspace.Mode` (not `podman bool`) to decide the rootful `<uid>` suffix: `tpd-svc-<name>` rootless, `tpd-svc-<name>-<uid>` rootful.
- `tpd.uses-service` is set on the main container's labels in `buildSpec` by scanning `cfg.Mounts` for `Service != ""` and collecting the comma-joined set of service names.
- Service `files:` are written via `CopyToContainer` inside `StartServices` (after container create, before start), owned by root (uid 0).
- Rootful socket chown: the main container's bootstrap chowns the socket **mount targets** (the `mounts:` key, which is an in-container path), not the host run-dir path. `Spec.SocketPaths` holds the mount *targets*; `CreateContainer` adds them to the bootstrap's `writable` chown list.
- `StartServices` must `ensureImagePulled` and `ResolveImageID` for the service's base image before creating the service container (and before computing the derived tag if `packages:`/`repos:` are declared). `--pull` is forwarded to refresh mutable tags. **On reuse, `--pull` still refreshes the base image** (the reuse path calls `ensureImagePulled` with `force=pull`); this may pull a new base image but does NOT recreate the running service (recreation is driven by the hash, which covers the image *name*, not the image *ID*). A future enhancement could detect a changed base image ID and recreate; out of scope for v1.
- **Reuse never probes.** When a running service is reused (hash matches), no socket probe runs and bindings come from the deterministic run-dir path. **Hash mismatch with consumers is a hard error** (not warn-and-reuse): the launch fails with a clear message naming the consumer container(s) ("service <name> is running with a different config and is in use by container(s) <names>; stop them or rename the service"). The consumer names are included so the user can find and remove the blocking containers. This avoids both the dead-socket problem and the lock-leak-on-missing-key problem.
- Expose parent-dir bind mounts are **deduplicated**: two exposes sharing the same parent dir (`/run/a/x.sock`, `/run/a/y.sock`) produce one mount, not two.
- **Service mounts do NOT include the workspace.** The service container must not have access to the user's project. `StartServices` builds its own mount list (cache mounts + deduped expose parent-dir bind mounts + service host-bind mounts) — it does **not** call `buildMounts` (which unconditionally adds the workspace bind). The service container also inherits `SecurityOpt: d.securityOpts()` (same as the helper container in `docker_prepare.go`) so SELinux-enforcing hosts don't relabel the run-dir bind-mounts.
- **Service path semantics in `ResolveTildes`:** service mount *sources* are host paths and expand against `hostHome` (the host user's home). Service mount *targets*, cache paths, and file targets are in-container paths and expand against `/root` (services run as root with `HOME=/root`). Env values are template-rendered only (no tilde expansion — same as the main profile's env).
- **Services are rootless-only.** `StartServices` checks `spec.Workspace.Mode` and returns a hard error if `ModeRootful`: rootful mode can't write `/run/tpd-svc-<name>-<uid>/` as the host user, and a root-created socket isn't connectable by the host user's probe. Rootless (where container root maps to the host user) is the primary target and works correctly.
- **`StartServices` releases all acquired locks on every error path.** A `defer` inside `StartServices` releases locks acquired so far; the release func is set to a no-op before returning successfully (the caller takes ownership via `ServiceBindings.Release`). Without this, a socket-probe timeout on service 2 of 3 leaves service 1's lock held; the deferred `StopServices` then flocks the same path from a new fd and deadlocks (flock is per-open-file-description, not context-aware; the 30s timeout context doesn't help).
- **`StopServices` consumer lookup** uses a label-presence filter (`tpd.uses-service` exists) plus an in-Go match (split the comma-joined value, trim, check membership). A label *value* filter can't do substring matching reliably (a service named `a` would match `ab,cd`).
- **Every return after `StartServices` succeeds must call `Release()` first.** A return without releasing the lock causes `StopServices` to self-deadlock on the same flock. `Release` is a nil-safe, once-only closure (calling it twice is a no-op).
- **`serviceRunDir` and `serviceLockfilePath` are package-level vars** in `docker_services.go` (not methods), overridable in tests via assignment. This provides the seam for socket-probe and lock-ordering tests without exposing internals. The lock type is `unix.LOCK_EX`.
- **Socket names (Exposes keys) are validated** against `profileNameRe` — a key with `/` or spaces makes the `<service>/<socket>` binding key and error strings ambiguous.
- **`read_only: true` on a service-socket mount is rejected** by validation — a read-only bind fails `connect()` with `EROFS`.
- **Cache names share the `tpd-cache-<name>` namespace** with the main profile and other services. Two services (or a service and a profile) declaring `caches: data:` share one volume. This is intentional (same as today's cross-profile sharing) and documented; subpaths keep different targets separate within the volume.
- **Hash truncation: 12 hex chars (48 bits)** — 8 hex (32 bits) is too collision-prone for a "silently stale daemon" failure mode. The cost of 4 extra chars in a label is negligible.
- **`tty` is re-derived in `RunContainer`** from `spec.TTY` and `term.IsTerminal(os.Stdout)`, not passed via `CreateResult` (which carries only `ContainerID`). `CreateContainer` computes `tty` for the `ContainerCreate` config; `RunContainer` re-derives it for the raw-mode setup. Both use the same expression: `spec.TTY == "true" || ((spec.TTY == "auto" || spec.TTY == "") && term.IsTerminal(int(os.Stdout.Fd())))`.

        - /var/lib/registry

```go
func (m *Mount) UnmarshalYAML(value *yaml.Node) error {
	type plain Mount
	var raw plain
	if err := value.Decode(&raw); err != nil {
		return err
	}
	*m = Mount(raw)
	m.ReadOnly = true
	if m.Service != "" {
		m.ReadOnly = false
	}
	if value.Kind == yaml.MappingNode {
		for i := 0; i+1 < len(value.Content); i += 2 {
			if value.Content[i].Value == "read_only" {
				if err := value.Content[i+1].Decode(&m.ReadOnly); err != nil {
					return err
				}
				break
			}
		}
	}
	return nil
}
```

func (m Mount) MarshalYAML() (interface{}, error) {
	out := struct {
		Source   string `yaml:"source,omitempty"`
		Service  string `yaml:"service,omitempty"`
		Socket   string `yaml:"socket,omitempty"`
		ReadOnly *bool  `yaml:"read_only,omitempty"`
		Optional bool   `yaml:"optional"`
		Create   bool   `yaml:"create,omitempty"`
	}{
		Source:   m.Source,
		Service:  m.Service,
		Socket:   m.Socket,
		Optional: m.Optional,
		Create:   m.Create,
	}
	defaultRO := true
	if m.Service != "" {
		defaultRO = false
	}
	if m.ReadOnly != defaultRO {
		ro := m.ReadOnly
		out.ReadOnly = &ro
	}
	return out, nil
}

package profile

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"sort"
)

func computeServiceHash(svc Service) string {
	h := sha256.New()
	fmt.Fprintln(h, svc.Image)
	for _, p := range sortedStrings(svc.Packages) {
		fmt.Fprintln(h, p)
	}
	for _, name := range sortedKeys(svc.Repos) {
		r := svc.Repos[name]
		fmt.Fprintf(h, "repo %s %s %s %s %s %s\n", name, r.ExtRepo, r.URL, r.KeyURL, r.Suites, r.Components)
	}
	for _, target := range sortedKeys(svc.Files) {
		f := svc.Files[target]
		mode := f.Mode
		if mode == 0 {
			mode = 0o644
		}
		fmt.Fprintf(h, "file %s %o %s\n", target, mode, f.Content)
	}
	for _, c := range svc.Command {
		fmt.Fprintln(h, c)
	}
	for _, k := range sortedKeys(svc.Env) {
		fmt.Fprintf(h, "env %s %s\n", k, svc.Env[k])
	}
	for _, k := range sortedKeys(svc.Exposes) {
		fmt.Fprintf(h, "expose %s %s\n", k, svc.Exposes[k])
	}
	for _, target := range sortedKeys(svc.Mounts) {
		m := svc.Mounts[target]
		fmt.Fprintf(h, "mount %s %s %s %s %v %v %v\n", target, m.Source, m.Service, m.Socket, m.ReadOnly, m.Optional, m.Create)
	}
	for _, name := range sortedKeys(svc.Caches) {
		paths := svc.Caches[name]
		fmt.Fprintf(h, "cache %s %v\n", name, []string(paths))
	}
	for _, k := range sortedKeys(svc.Labels) {
		fmt.Fprintf(h, "label %s %s\n", k, svc.Labels[k])
	}
	sum := h.Sum(nil)
	return hex.EncodeToString(sum[:])[:12]
}

func sortedStrings(s []string) []string {
	out := append([]string(nil), s...)
	sort.Strings(out)
	return out
}

func sortedKeys[V any](m map[string]V) []string {
	keys := make([]string, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	sort.Strings(keys)
	return keys
}

3. **`StartServices(ctx, spec, w, pull)`** — first, check `spec.Workspace.Mode`; if `ModeRootful`, return an error ("services are not supported in rootful mode; use rootless podman"). Then acquire all service locks **in sorted service-name order** (sort the service names, then acquire locks one by one). This prevents deadlock across concurrent launches sharing multiple services. **Internal lock release**: a `defer` inside `StartServices` releases all locks acquired so far; the release func is set to a no-op before returning successfully (the caller takes ownership via `ServiceBindings.Release`).    - If present and hash matches: **reuse — no probe, no create**. Still call `ensureImagePulled(ctx, cli, svc.Image, w, pull)` to honor `--pull` on mutable tags. Bindings computed from the deterministic run-dir path: `serviceRunDir(name, mode) + exposePath`.

If >0, **hard error**: return an error **naming the consumer containers** ("service <name> is running with a different config and is in use by container(s) <names>; stop them or rename the service"). The consumer names come from the ContainerList response.

   - To create fresh:
     1. `ensureImagePulled(ctx, cli, svc.Image, w, pull)` — pull the service's base image (or refresh on `--pull`).
     2. `ResolveImageID(ctx, cli, svc.Image)` — get the base image ID (needed for `DerivedTag`).

- [ ] **Step 3: Update `LaunchWithWriter`**

In `pkg/tpd/launch.go`, the key ordering: **register `defer StopServices` BEFORE `StartServices`** so it runs on every exit path including `StartServices` failure. Then `StartServices` → rewrite mounts → `CreateContainer` → `Release` → `RunContainer`. **Every return after `StartServices` succeeds must call `Release()` first** — otherwise `StopServices` self-deadlocks on the same flock (flock is per-open-file-description; a new fd on the same path blocks).

```go
		// Register stop BEFORE StartServices so it covers the StartServices error path.
		if len(spec.Services) > 0 {
			defer func() {
				stopCtx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
				defer cancel()
				if err := rt.StopServices(stopCtx, spec); err != nil {
					fmt.Fprintf(os.Stderr, "tpd: warning: stop services: %v\n", err)
				}
			}()
		}

		var serviceBindings runtime.ServiceBindings
		if len(spec.Services) > 0 {
			bindings, err := rt.StartServices(ctx, spec, progress, opts.Pull)
			if err != nil {
				return Result{ExitCode: 3, Err: fmt.Errorf("start services: %w", err)}
			}
			serviceBindings = bindings
			for i := range runSpec.Mounts {
				m := &runSpec.Mounts[i]
				if m.Service == "" {
					continue
				}
				key := m.Service + "/" + m.Socket
				hostPath, ok := bindings.Sockets[key]
				if !ok {
					serviceBindings.Release()
					return Result{ExitCode: 3, Err: fmt.Errorf("service socket %s not found in bindings", key)}
				}
				runSpec.SocketPaths = append(runSpec.SocketPaths, m.Target)
				m.Source = hostPath
				m.Service = ""
				m.Socket = ""
			}
		}

		created, err := rt.CreateContainer(ctx, runSpec)
		if err != nil {
			if serviceBindings.Release != nil {
				serviceBindings.Release()
			}
			return Result{ExitCode: 3, Err: fmt.Errorf("create container: %w", err)}
		}

		// Release service locks now that the main container is created and
		// labeled with tpd.uses-service — a concurrent stop step can see it.
		if serviceBindings.Release != nil {
			serviceBindings.Release()
		}

		code, err := rt.RunContainer(ctx, runSpec, created)
		if err != nil {
			return Result{ExitCode: 3, Err: fmt.Errorf("run container: %w", err)}
		}
		return Result{ExitCode: code}
```

Note: `SocketPaths` holds the **mount target** (the `mounts:` key — an in-container path), not the host run-dir path. The bootstrap chowns in-container paths. Add `"time"` to imports.

func checkLeakedContainers(ctx context.Context, rt *dockerRT) Check {
	f := filters.NewArgs()
	f.Add("label", runtime.OwnershipLabel+"=true")
	containers, err := rt.cli.ContainerList(ctx, container.ListOptions{All: true, Filters: f})
	if err != nil {
		return Check{Name: "leaked containers", Status: Warn, Message: err.Error()}
	}

	consumedServices := map[string]bool{}
	for _, c := range containers {
		if c.State != "running" {
			continue
		}
		if c.Labels[runtime.ServiceRoleLabel] == runtime.ServiceRoleSidecar {
			continue
		}
		if uses := c.Labels[runtime.UsesServiceLabel]; uses != "" {
			for _, name := range strings.Split(uses, ",") {
				consumedServices[strings.TrimSpace(name)] = true
			}
		}
	}

	var leaked []string
	for _, c := range containers {
		if c.Labels[runtime.ServiceRoleLabel] == runtime.ServiceRoleSidecar {
			if c.State == "running" && consumedServices[c.Labels[runtime.ServiceLabel]] {
				continue
			}
			leaked = append(leaked, strings.Join(c.Names, ","))
		} else {
			leaked = append(leaked, strings.Join(c.Names, ","))
		}
	}
	sort.Strings(leaked)
	if len(leaked) == 0 {
		return Check{Name: "leaked containers", Status: Pass, Message: "none"}
	}
	return Check{Name: "leaked containers", Status: Warn, Message: strings.Join(leaked, ", ") + " (remove with: docker rm -f ...)"}
}
